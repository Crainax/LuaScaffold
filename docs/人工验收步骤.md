# 人工验收边界与步骤

本机禁止Windows桌面自动化。以下是尚未自动验证的真实界面/输入检查，不代表已经通过。自动CLI测试仍检查原生属性、生命周期、真实同步消息和OOS。

## 正式业务界面

1. 先确认没有其他游戏，再运行 VS Code 的“Lua: 启动开发地图（保留游戏）”。查看 Logger 对应项目目录，确认只有一次BOOT且无FAULT。
2. 实际点击三个英雄按钮，检查名称、技能、两项天赋、冷却/能量文字、镜头和选中单位；每个英雄选天赋，重复选择应显示拒绝而不重新加成。
3. 开始试炼，三英雄轮流施法。观察原生伤害、施法特效、Boss死亡和完成计数；重复开始不能回血补能量，结束/再开始不会清空技能冷却。
4. 快速多次点击，区分“已入队”“未入队”“业务拒绝”。等待提示不是发奖/伤害成功证明；本地未确认提示不会自动重试。
5. 更换分辨率检查按钮可点、文本不遮挡、控件未超屏。结束后人工关闭本次手动游戏；Play不自动结束游戏。

## 官方UI专项

在 `ui` 套件/示例中实际操作连续滚动、嵌套面板、鼠标穿透与裁剪外点击、滚轮和键盘焦点；检查模型是否越过视口、中文与输入法、多分辨率字体效果。原生参数读回及人工触发Lua事件不能替代这些像素和输入检查。字号不是任意扩大保证，见UI原生链路报告。

## 地图编辑器

复制一个已构建MainMap/UnitTestMap的w3x，用编辑器打开副本，核对预放置训练目标、区域、地形与三个英雄物编；不保存覆盖已验地图。编辑源LNI时同步维护必要初始化与身份清单，再重建，不用小型夹具生成器覆盖任意完整地图。

## 真实玩家退出/网络

另开人工维护的多人测试会话，在一位玩家施法期间主动退出；检查其他端的退出事件、该玩家挑战结束且无奖励、当前自有英雄/召唤物清理、借用对象与已转移对象保留。保存剩余端日志及房主记录。自动测试要求每端完成，不能把退出导致缺少完成标记的场次当正常PASS；跨机断线/重连仍需独立测试方案。

当前代码不提供重连、托管、共享控制或平台补偿事务。模拟退出通知已验证的内容仅限清理策略和相关资源路径，不能据此宣布实际网络断线经过验证。
