# 计时、事件与开发 UI 热更新

## 便利计时 API

本模板提供 `local ac = require('scaffold.ac').new(bridge, ui)`，不会把上游 ac 装入全局。同步代码可使用 `ac.wait(ms, fn)`、`ac.loop(ms, fn)`、`ac.timer(ms, n, fn)`；0 次表示持续循环，wait 表示一次。返回 token 支持 remove/cancel、pause、resume、get_remaining；回调收到自己的 token。

```lua
local ac = require('scaffold.ac').new(bridge, ui)
local tick = ac.loop(1000, function(task)
    -- 此处是在全端一致的同步逻辑中创建的任务。
    -- 需要停止时 task:remove()。
end)
scope:defer(function() tick:remove() end)
```

业务通常不再自行 CreateTimer。桥接层持有一个原生 0.01 秒周期 timer，Lua 任务共享其整数 tick。毫秒参数向上取整到至少 1 tick；10ms 是请求分辨率，实际墙钟可能更慢。ac.clock() 是共享逻辑秒数，不是精确现实时间。

`ac.ui.wait/loop/timer` 是本地显示任务；与面板有关的任务更建议 `panel:wait/loop`，因为销毁面板会自动取消。不要在 UI 点击中调用同步 ac.wait 来“把本地操作变同步”：它会被上下文检查拒绝。点击先 bridge:send，接收端通过鉴权再修改玩法或安排同步任务。

底层 `Scheduler.new()` 默认 sync，也可显式传 local；本地调度器执行回调时自动进入 local 上下文。不同客户端本地任务数量、暂停状态和实际耗时可以不同，不能用它们决定玩法。调度器仍是简单任务表扫描加到期 ID 排序，适合基线的有界任务量；不是已经验证十万任务的高性能时间轮。

任务在同一 tick 按创建序号执行。回调中新建任务最早下一个 tick；取消可阻止本 tick 尚未执行的任务；暂停保存剩余 tick，resume 重新计算到期 tick。callback 出错停止调度器并释放回调引用，不尝试在单端继续恢复同步状态。取消和 stop 都有“外部仍持有 token，捕获数据仍能被 GC”的回归用例。

已排入本 tick 候选列表的任务若被前一个回调暂停或推迟，也不会按旧到期时间执行。UI 服务 stop 后的 wait/loop/timer 和 register_event 会立即拒绝，且不增加任务/事件计数；停止后的服务不支持重新启动。

## 事件

`Events.new('sync'|'local')` 提供 on、emit、clear、count。on 返回幂等注销函数；同一派发中新注册的监听不加入该次派发，尚未执行的监听若被注销则跳过。监听按注册顺序调用；返回 true 汇总为处理结果，后面的监听仍会执行。错误重新抛出，内部派发深度和延迟压缩状态会恢复。

嵌套 emit 是另一次派发，因此能看到此前已注册的新监听。同步事件拒绝从 local 域操作；本地事件的监听自动进入 local 域。仍不能拦截直接 native 调用，这是一组帮助开发者发现越界的规则，不是安全沙箱。

## Lua 不自带完整热更新

Lua 提供 load、函数值和模块缓存，框架可以基于它们实现更新。`package.loaded[name]=nil` 后 require 只是重新执行模块；旧 closure、timer、事件、对象实例与原生资源不会自动换成新的，也不自动恢复失败前状态。

本模板只提供开发 view 更新，不重载 renderer、同步桥、单位系统或玩法定义。正式构建 dev=false，并且 MPQ 中不包含 src/dev 和 src/probes。原包 F5/load 解码器仍被禁用。

启动：选择 task “Lua: 启动开发地图（保留游戏）”，将 `examples/dev_view.lua` 或 `examples/scroll_view.lua` 放到游戏目录 `LuaScaffold-dev/view.lua`。派生项目目录使用 `<project-id>-dev/view.lua`。loader 每 500ms 本地轮询一次，文件限 128 KiB，只在内容变化后尝试更新。

文件返回 `function(ctx)`：通过 ctx:create 建控件，ctx:on 注册事件，ctx:wait/loop 安排本地任务，ctx:send 发送受验证命令。ctx.state 只保存普通数据，用于下一版视图；不允许函数、原生对象或循环引用。原生句柄是数字，校验无法识别其语义，开发者仍不得把 handle 当持久化状态。

更新流程先创建隐藏候选树、绑定候选资源，成功后才切换可见界面并清理旧树。编译/构建失败清理候选，保留旧树和旧状态。只有在工厂遵守 ctx 的所有权约定时才有这个恢复保证；工厂直接访问外部全局或原生做副作用无法自动撤销。开发环境减少可见全局，但不是面对恶意代码的隔离器。

旧视图清理失败时停止接受后续更新并报告错误，不能声称已回滚引擎资源；需要重启测试局。不要在 dispose 中执行可能改变同步玩法的逻辑，也不要自行使用原生销毁破坏整个控件树。

## 验证范围

离线及原生测试重复 30 次成功更新与 30 次创建中途失败，检查 state 保留、控件/任务/事件返回基线、weak payload 可回收，并验证 disabled 模式拒绝更新。原生文件探针实际写入源码，经过相同轮询入口完成首次加载、语法失败、有效编辑恢复和停止。

文件探针发现内置 os.remove 不可用，所以结束后将本次专用测试文件清空；不假定宿主 Lua 标准库的全部函数都存在。开发日志中 `[DEV_VIEW_REJECTED]` 是被正确拦下的候选失败，不等于同步错误。生产代码错误仍以 FAIL/错误日志处理。

扩展到其他模块时：无副作用的纯配置可通过验证后替换数据；持有对象的模块要定义迁移和卸载；同步玩法必须保证所有客户端收到同一版本、在一致时刻切换并迁移同一状态。后两项没有在本模板实现，修改此类代码应重启地图。
