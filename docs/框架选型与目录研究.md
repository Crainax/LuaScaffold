# 框架选型与目录研究

2026-11-12 的选择是保留固定 InnerJAPI 1.49-9 载体与官方 UI，采用项目自己的小型基础层。没有找到经本次审查、可直接替换且已经证明兼容这个二进制版本的第三方完整框架。“功能更多”不足以证明更适合当前模板；未运行的候选不能宣称性能或多人安全优于现有实现。

GitHub 搜索覆盖 InnerJAPI lua、Warcraft Lua 框架及相关项目。固定源码链接和树标识记录在 `research/upstream-sources.json`；本地文件哈希见 `research/local-sources.json`。这些是选型审查，不是对整库所有业务的代码审计。

## 从候选中吸收什么

`src/scaffold` 只负责边界、协议、生命周期和通用调度；`src/ui/base` 只承载引擎 UI 适配；`src/app` 装配具体项目。新项目可在 app 下增加 gameplay、ui、data、services，或在规模增大后提为独立同级目录。技能、物品、伤害和平台存档有真实需求再引入，不为凑“完整框架”预先写一遍。

`src/probes` 是原生实验，`src/dev` 是开发工具，两者在正式包中排除。`tests` 的宿主 Lua 测试用来验证语言层语义；`tests/evidence` 保存游戏记录；`research` 保存来源与二进制分析证据。发行构建不是简单把整个项目根目录塞入 MPQ。

时钟采用同步与本地明确区分的入口；事件返回注销函数；UI 更新通过拥有根控件的 view scope 替换。以上吸收的是设计方式，没有直接拷贝第三方框架实现。

## 需要警惕的实际差异

MoeHero 的事件倒序分发，可通过非 nil 返回值中断；本模板事件按注册顺序执行，返回 true 表示处理结果但不阻止后续监听。不能只因为 API 都叫 event 就互换。其 trigger:remove 延迟从数组移除，持有 token 仍可能持有 callback；本模板注销立即清空回调引用，并明确派发中增删的语义。

MoeHero 的开发 reload 临时改写全局 require、替换技能/buff 定义，并遍历现有英雄修复状态；其发布 hot_fix 则同步补丁版本、签名和内容。前者不能自然推广到多人局，后者也不是“Lua 自带热更新”。魔灵的 timer_ex 仍创建原生 timer，说明看到 ac.xxx 并不能推断其内部不会创建句柄。

fulu 的 event.off 在数组中置 nil，emit 仍以 `#list` 为边界。Lua 对有洞数组的长度没有所期望的稳定含义，因此不照搬这种存储方式。其注释把部分逻辑称为“主机/服务器执行”，不能替代 Warcraft 多端同步执行模型的验证。热更通过清 package.loaded 后 require，并调用新模块 OnReload；这不能证明旧模块持有的资源已被释放。这里是源码风险判断，未对该地图做游戏实测。
