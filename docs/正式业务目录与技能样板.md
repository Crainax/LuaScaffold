# 正式业务目录与技能样板

实际实现三个英雄类型，而非十个空目录。每位玩家拥有三名英雄，1/3/6 客户端分别建立 3/9/18 个英雄实例。目录按业务归属组织，公共机制与地图规则分开。

```text
src/
  app/main.lua                     唯一应用组装、启动、停止
  world/session.lua                地图会话、命令分发、服务所有权
  world/arenas.lua                 地图场地坐标
  content/heroes/catalog.lua       确定的英雄注册顺序
  content/heroes/reimu/            definition、talents、skills/spirit_bolt
  content/heroes/marisa/           definition、talents、skills/stellar_beam
  content/heroes/sakuya/           definition、talents、skills/returning_blades
  content/effects/cast_aura.lua    公共施法特效数据
  content/challenges/training/    具体挑战定义和 Boss 行为
  systems/heroes/service.lua      英雄实例、队伍恢复
  systems/talents/service.lua     天赋选择/权限/一次选择规则
  systems/challenges/service.lua 副本公共流程、胜败与清理
  rules/combat.lua                本地图伤害和天赋公式
  presentation/challenge_view.lua 本地 UI 与命令提交
  scaffold/                      公共调度、事件、ID、命令与引擎桥
  game/unit/                     公共单位对象与原生事件桥
  game/skill/service.lua          公共施法事务和生命周期
  game/combat/native.lua          原生敌我、范围、伤害、特效适配
  ui/base/                       官方 UI 的适配副本
  probes/                        仅测试的生命周期、性能、业务等探针
  dev/                           仅开发的受控 view 热更新
maps/MainMap/                     正式地图 LNI 源
maps/UnitTestMap/                 单测地图独立 LNI 源
config/                          固定工具及构建策略
tools/                           构建、启动、模板、依赖和证据工具
tests/                           离线回归；历史 evidence 不复制到新项目
```

这是脚手架研发仓库布局。派生项目默认把公共 `scaffold/ui/game/vendor` 放到 `deps/lua-scaffold`，其余业务留在 `src`。仍然 `require 'game.skill.service'`，构建器从 `framework.lock.json` 锁定包取文件，不需要原脚手架目录存在。业务禁止同名覆盖公共模块。公共层修复应导出新包、显式升级并回归，不能引用开发者机器上随时变化的路径。

## 功能归属

| 功能 | 位置 |
| --- | --- |
| 英雄专属技能、天赋数值 | `content/heroes/<key>/skills` 与 `talents.lua` |
| 多英雄共享技能或效果数据 | `content/skills`（按需新增）、`content/effects` |
| 通用施法、中断和资源所有权 | 公共 `game/skill` |
| 暴击、护甲、属性等地图公式 | `rules/combat` 和地图系统 |
| 副本开始/结束、实例 ID、清理 | `systems/challenges` |
| 某副本/Boss 的阶段和技能 | `content/challenges/<key>` |
| 天赋点数、解锁和重置系统 | `systems/talents` |
| HUD、技能面板、提示 | `presentation` |
| 物编、预放置、音频/模型 | 两张地图各自的 LNI 源分类 |
| 后续装备定义/库存与穿戴流程 | 按需增加 `content/items` / `systems/inventory`，本轮不创建空实现 |

第四个英雄新增目录并显式加入 catalog；不能依靠扫描文件或未排序 pairs 决定注册顺序。英雄数量增加不要求复制整套控制器。两个地图分别维护物编或显式生成共享部分，不能暗中依赖 UnitTestMap 的对象存在。

definition、skill 和 challenge 是共享只读配置；单位ID、能量、冷却、天赋选择、cast scope和challenge session是各实例状态。多个玩家复用同一英雄定义，不把玩家数据写回 require 得到的共享表。

## 技能完整路径

本地按钮 → bridge 发送队列 → 原生同步消息 → 引擎发送玩家 → 协议/授权/重放校验 → world 业务检查 → skill 检查存活、权限、目标、距离、能量和冷却 → 准备监听、特效、单位任务 → 提交能量/冷却 → 延迟原生伤害 → 完成或中断清理。

`bridge:send` 成功返回本地序号，只表示已入队。协议接受也不等于技能成功；业务结果携带请求seq，本地界面只用相同seq确认最新请求，旧结果不能替新请求报成功。队列最多32条、每10 tick发送一条；满队列的新请求不入队。界面等待10000毫秒的本地调度时间后显示“暂未确认”，不推断失败、不自动重试；迟到的匹配结果仍可确认。它不是网络送达保证或精确墙钟超时。

| 英雄 | 技能 | 基础行为 | 天赋二选一 |
| --- | --- | --- | --- |
| 灵梦 H001 | spirit_bolt | 前摇30 tick，60伤害，耗能20，冷却200 tick | 伤害+25% / 距离+200 |
| 魔理沙 H002 | stellar_beam | 前摇20 tick，间隔20 tick，3×25伤害，耗能30 | 多一段 / 每段+8 |
| 咲夜 H003 | returning_blades | 前摇10 tick，间隔15 tick，3×18伤害，耗能15 | 多一段 / 伤害+30% |

逻辑 tick 请求间隔为 0.01 秒，实机不保证100 tick恰好一秒。玩法用逻辑 tick，墙钟只作诊断。能量是 Lua 逻辑属性，未绑定原生 mana。三个技能复用有界多段施法机制，并非任意弹道/BUFF 编辑器。

施法拥有独立 scope。准备失败时清理已分配特效、监听和任务，不扣能量或设置冷却；提交后因死亡、目标移除、所有权/形态变化、超范围等中断不退款。原生伤害可能同步触发死亡并重入清理，返回后必须再次检查 cast.active。天赋变更不重置已有冷却/能量。

## 挑战与结算

训练 Boss n001 有180 HP，以原生伤害脉冲攻击队伍，半血增强。会话拥有 Boss、计时任务和监听。胜利计数只增加一次；超时、全灭、主动离开和目标外部移除分别结束。会话 ID 不复用，旧请求不能结束新会话。重复开始先拒绝，不能借无效请求回血或恢复能量。正式游戏可移动；测试暂停普通移动以固定实验条件。

结束恢复英雄并保留冷却，天赋单局一次选择。本样板没有物品奖励和平台存档。新增奖励应在同步结算点幂等执行，另测平台失败，不能从本地 UI 提示直接发奖。真实断线/重连恢复不在本轮覆盖中。

玩家退出采用原生 EVENT_PLAYER_LEAVE → 单位服务事件 → world:leave_player。先标记退出并拒绝新业务，再结束挑战（不奖励、不恢复队伍），按稳定ID清理该玩家当前拥有的受管单位、施法和召唤物。借用对象不销毁，已转移给其他玩家的单位保留；未知玩家和重复退出不重复清理。离线及注入退出通知可验证清理策略，不能冒充真实网络断线测试；回放、重连、托管/共享控制另行设计。

## 初始化与开发热更

JASS 先建立地图预放置和区域，再执行一次 Lua 引导；`world/generated_placements.lua` 由构建生成，不在 src 手改。夹具生成器不是任意地图反编译器。正式 MainMap 排除 runtime_test、旧测试 UI app/view、probes 和 dev。

开发热更仅限受控本地 view；整个应用一局启动一次。技能、单位、挑战和公共模块不随本地文件更改重载。依赖升级/回退与两图 LNI 构建见《固定依赖与LNI构建》。原生通过范围以测试报告和每端日志为准，自动 UI 派发不等于真实鼠标和像素验收。

## 日常计时怎么写

单位动作优先 `units:after(unit_id, ticks, callback)`，自动绑定当前生命周期。普通同步任务可用 `bridge.scheduler:after(ticks, callback, interval)`，或 `local ac = require('scaffold.ac').new(bridge, ui)` 后使用 `ac.wait(ms, fn)`、`ac.loop(ms, fn)`、`ac.timer(ms, count, fn)`。这是本框架便利层，不是直接加载原包 ac。返回任务/token 必须交给所属 scope 或主动 cancel/remove；循环任务不能靠 GC 结束。

UI任务用控件自身 `wait/loop` 或本地UI调度器，销毁控件时取消。匿名函数可以正常使用，关键是持有者、捕获量、解除路径和调用频率。业务无须为每个技能调用 CreateTimer；名称 ac 也不会把本地调用变成同步。不能在UI、文件热更或本地计时回调里调用同步 ac/单位任务安排玩法。`ac.clock()` 是逻辑时间，`os.clock()` 只适合本地诊断，不用于技能冷却或同步补偿。
