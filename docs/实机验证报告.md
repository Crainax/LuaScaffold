# LuaScaffold 0.1.0 实机验证报告

日期：2026-11-12。结论：官方 UI 已接入；当前代码通过固定本机环境的单人、三客户端、六客户端验证，具备作为新 Lua 项目基础模板的条件。这里的结论针对本报告覆盖的基础层和场景，不代表任意后续业务或所有平台都不会 OOS。

## 环境和可追溯性

- Warcraft III：`1.27.0.52240 (f7ba2a3)`，本机 `war3.exe` 文件版本。
- InnerJAPI：用户提供的 1.49-9 固定载体，78 个上游文件逐一 SHA256 校验；三项核心运行载体哈希见 `vendor/war3ui-1.49-9/README.md`。
- 游戏日志实际启动信息：`Lua 5.3`，`jass.runtime.version = 3`。这个数字不是 InnerJAPI 发布版本号。
- 离线 Lua：5.3.6。地图打包使用 YDWE 1.32.13 的 StormLib；经典 JASS 使用 KKWE 的 pjass-classic 校验。
- 联机：同一台机器的独立客户端，使用 `D:/War3/tools/LanTest`、YDWE 自动入房及 ydhost。没有使用通用 Windows 桌面控制。
- 每局保存原地图 SHA256、客户端 PID/创建时间、构建文件哈希、每端日志、房主日志、结果及清理记录。`tests/evidence/index.json` 是全部七场的索引。
- 六客户端最终构建 `ui-six-02.w3x` SHA256：`bf84d58308b35c37a9f6680212b271367290526e45b8262659f350c847e8f1b3`。
- `python tools/verify_evidence.py` 独立核对每端状态序列、完成标记、故意 OOS、清理结果，以及当前 Lua 源码与最终六人测试构建的字节一致性。Git 对运行 Lua 保留原始字节，避免换行转换破坏这项核对。

## 六客户端压力及同步证据

| 客户端 | UI 创建销毁组数 | 业务 RNG 调用 | 一致状态轮次 | 完成断言 |
| --- | ---: | ---: | ---: | ---: |
| P1 | 493 | 237 | 23 | 25 |
| P2 | 976 | 237 | 23 | 25 |
| P3 | 1459 | 237 | 23 | 25 |
| P4 | 1942 | 237 | 23 | 25 |
| P5 | 2425 | 237 | 23 | 25 |
| P6 | 2908 | 237 | 23 | 25 |

合计 10,203 组，每组包含 panel/button/text/edit。各端数量故意不同，P1 还在每批 UI 压力后额外执行全量 GC，其他端保持正常 GC。各端都检查销毁后回到注册表基线，最终 UI 关闭后控件数为零。

同步侧创建六个相同类型、相同初始位置的单位，通过 group 枚举候选后按稳定 entity ID 排序再随机选择。循环修改生命值，并每十次随机调用删除一个实体、移除单位后重新创建，检查旧 ID 失效、新 ID 不复用。状态摘要包含业务累计值、稳定 ID、生命、量化坐标及每玩家命令次数，不包含 handle、frame ID、Lua 地址或内存值。

每端都通过真实 SendCustomMessage 通道提交同一逻辑阶段的摘要，并检查所有活动玩家的摘要与本端期望一致。事后工具再次跨日志比较 phase/hash/RNG 序列。两种检查均通过，房主没有正常场景的 OOS 报警。此测试没有强制让原生 handle 数字不同，也没有证明所有 handle 引用模式安全；它验证的是不对称本地 UI/GC 与当前同步逻辑的隔离。

测试构建运行 12,000 个共享逻辑 tick，再等待 300 tick 输出完成标记。实际从 BOOT 到完成约 151 秒；请求的 0.01 秒原生计时器不等于可保证的实际精度。**不是 30 分钟浸泡测试**，没有据此声明长期原生内存无增长。

## UI、闭包与消息

- 实际创建官方 frame，检查按钮宽度大于零和文本读回；常用控件多轮创建销毁，重复 destroy 不重复释放。
- model、model2、滚动面板、进度条均在实机创建销毁。model2 有一个单局共享背景，测试预热后将其计入基线；最终 stop 一并销毁。
- 空滚动内容、进度条 `0/0` 已覆盖；UI 全局隔离和标准弧度 math 保持通过。
- 取消控件长任务后，闭包捕获对象的弱引用消失。离线还验证外部保留 token、暂停任务和整体停止时的释放。
- 每端创建 8 个真实 TimerStart 回调并捕获独立标记，PauseTimer/DestroyTimer 后主动 GC，观察 `retained=0/8`。证明该固定版本、该销毁路径下这组标记可释放；不推广为所有 native 注册 API 都会自动释放闭包。
- 模拟点击从真实 Lua UI 事件入口进入，再经过真实同步消息通道；没有用系统鼠标键盘。重复发送同一个原始消息，最终每名玩家 ping 只执行一次。
- 纯 Lua 层覆盖恶意格式、超长数据、非法整数、白名单/授权、旧序号/重复序号、发送者隔离。发送端有 32 项上限及每十 tick 一项节流；未实现不可信客户端的全套防作弊或可靠重传协议。

## 离线、构建和模板复用

`tests/evidence/offline-validation.txt` 保存：78 个上游文件哈希、全部新 Lua 语法、10 项纯 Lua 用例、6 项原包问题复现、bridge mock 和 100 组 UI mock 生命周期。

发行构建 `build/starter-0-1-0.w3x` 已完成 JASS 校验及 50 个文件逐一 MPQ 回读。发行 payload 43 文件；不含 runtime_test、旧 UI 同步解码器、F5 热更新或原包业务入口。

`tools/reuse_check.py` 在独立临时目录实际复制模板，改项目 ID 为 FreshLuaGame、使用中文地图标题，再完成发行构建及 MPQ 回读，检查最终 manifest 与所有 payload 文件一致。没有复制旧 `.git`/`build`，测试副本结束后清理。证据见 `tests/evidence/reuse-check.json`。这项是复制和构建验证，不冒充复制后的地图再次实机测试。

## 明确未覆盖

1. KK/11 等平台在线房间、跨机器网络、高延迟/丢包、断线退出、观战与回放。
2. 其他 Warcraft/InnerJAPI 版本、handle_level 1/2、同局热重载、多个插件抢占相同原生入口。
3. 30 分钟以上压力、原生内存/handlecount 连续走势、完整 TriggerAddAction 及其他原生回调释放矩阵。
4. 真实鼠标拖动、键盘输入、中文输入法、各分辨率视觉验收、全部官方 UI 方法。
5. 实际 RPG 的单位自动登记、变身/召唤/复活、背包、技能、伤害、存档、支付及平台业务。

这些边界不会阻止把它作为新项目起点，但扩展到相应范围时需要对应验收，不能用本次基础层测试代替业务测试。
